# Working in HCGateway

This repository contains four coupled systems: the React Native Health Connect
client, Flask REST API, background analytics worker, and MongoDB persistence.
Read `doc/session-handoff.md` before making broad changes and use
`doc/frontend-data-model.md` for the prepared analytics contracts.

## Safety and repository boundaries

- Treat `db/`, local `.env` files, `api/service-account.json`, tokens, and raw
  health records as sensitive data. Agents are explicitly allowed to read and
  decrypt health records when needed for a user-requested analysis, diagnostic,
  verification, or analytics change. Prefer aggregate findings and minimize raw
  values in command output and chat responses. Never commit raw health records,
  credentials, or secrets.
- `db/` is a bind-mounted MongoDB data directory. Do not edit its files or run
  destructive database operations unless the user explicitly requests them.
- `docker compose down` preserves `./db`; never add `--volumes` unless deletion
  is intentional and explicitly authorized.
- Preserve unrelated work in a dirty tree. Inspect `git status` before edits
  and do not reset or discard user changes.
- `/root/health-connect-dashboard-for-fitbit` is a separate frontend repository.
  It may be inspected when relevant, but do not modify it without explicit
  authorization.

## Canonical backend behavior

- Raw encrypted Health Connect records are the source of truth. Prepared data
  is generated by the separately running analytics worker.
- The current analytics algorithm is `health-analytics-v8.3`; the focused-day API
  contract is `health-day-v1`.
- Prefer `GET /api/v2/analytics/day?date=YYYY-MM-DD&radius=7` for the day UI.
  Missing health metrics must remain missing and carry their API `status` and
  `note`; never silently turn absence into numeric zero.
- Sleep belongs to the configured local calendar date on which the session
  ends. Preserve the reconciliation, source-selection, and day-splitting rules
  documented in `doc/frontend-data-model.md`.
- Strain is an experimental, non-proprietary cardiovascular estimate. It must
  not be described as WHOOP's formula or as a clinical measurement. Withhold a
  score when personal zone calibration or heart-rate coverage is insufficient.
- Recovery is a provisional, non-clinical heuristic. Scores without HRV remain
  `partial`; preserve model versions, component quality, limitations, and the
  documented future-validation markers.
- `GET /api/v2/sync/status` is a server-observed upload heartbeat. “Active”
  means an authenticated upload arrived within 120 seconds; it does not prove
  the Android foreground task is alive.

## API and documentation

- Routes live in `api/apiVersions/v2/routes.py`.
- `doc/api-documentation.yml` is the manually maintained OpenAPI source; update
  it whenever an endpoint, parameter, response, or status meaning changes.
- Update `doc/frontend-data-model.md` for frontend-facing analytics semantics
  and `doc/session-handoff.md` for meaningful operational checkpoints.
- Keep response changes additive when practical. Version deliberate contract
  breaks instead of silently changing existing meanings.

## Verification and operations

Run the complete test suite against the Compose database:

```bash
docker exec hcgateway_api sh -lc \
  'TEST_MONGO_URI="$MONGO_URI" python -m unittest discover -s tests -v'
```

Useful checks:

```bash
docker compose ps
docker compose logs --tail=200 analytics-worker
curl http://localhost:6644/health
./calculate-database-folder-disk-usage-in-gigabytes.sh
```

When source or dependencies change, rebuild both API and worker through
Compose. Keep the MongoDB image pin and `GLIBC_TUNABLES` workaround until the
host kernel caveat in `doc/frontend-data-model.md` has been resolved and tested.
